## 1. 初始化教学版 Go Module

检查时，工作区内的 Go 为 `1.26.4`，goctl 为 `1.10.2`。本轮使用 go-zero `v1.10.3`，明确固定版本。

在终端执行：

```bash
cd /Users/yz1/MyLab/mylab-course
go version
go mod init github.com/yz1qaq/MyLab/mylab-course
mkdir -p services/lab-api
```

`go mod init` 创建本目录的 `go.mod`，其中模块名也是生成代码 import 路径的前缀。本目录不再单独初始化 Git 仓库。

## 2. 手写接口定义

新建 `/Users/yz1/MyLab/mylab-course/services/lab-api/lab.api`：

```go
syntax = "v1"

type HealthResp {
    Status string `json:"status"`
}

service lab-api {
    @handler Health
    get /healthz returns (HealthResp)
}
```

这是 goctl 的 API 描述语言，不是可执行的 Go 代码：

- `HealthResp` 描述响应结构，JSON 字段叫 `status`。
- `get /healthz` 定义 HTTP 方法和路径；本接口没有请求体。
- `@handler Health` 决定生成的处理函数和相关逻辑名称。
- 此文件描述接口契约，返回什么业务值则由 Go 逻辑实现。

## 3. 生成框架代码并固定依赖

仍在 `/Users/yz1/MyLab/mylab-course` 执行：

```bash
goctl api go --api services/lab-api/lab.api --dir services/lab-api --style go_zero
go get github.com/zeromicro/go-zero@v1.10.3
go mod tidy
```

生成命令会根据已有模块名生成正确的 import。`--style go_zero` 指定文件名使用下划线，因此本轮文件名是 `health_logic.go`、`health_handler.go`。

主要文件如下，先关注启动与一次请求经过的文件：

```text
services/lab-api/
├── lab.api                         接口契约，学习者编写
├── lab.go                          服务入口
├── etc/lab-api.yaml                服务名称、监听地址、端口
└── internal/
    ├── config/config.go            配置结构
    ├── svc/service_context.go      组装并共享服务依赖
    ├── handler/routes.go           注册路由
    ├── handler/health_handler.go   HTTP 请求与响应的衔接
    ├── logic/health_logic.go       本轮要补充的逻辑
    └── types/types.go             从契约生成的 Go 数据类型
```

goctl 帮助生成重复的框架代码。学习者需要理解执行链、亲手编写契约与逻辑，并用请求确认行为。

## 4. 手写健康检查逻辑

打开 `/Users/yz1/MyLab/mylab-course/services/lab-api/internal/logic/health_logic.go`，保留生成的 import、结构体和构造函数，只把 `Health` 方法完整替换为：

```go
func (l *HealthLogic) Health() (resp *types.HealthResp, err error) {
    return &types.HealthResp{
        Status: "ok",
    }, nil
}
```

该方法由生成的 `HealthHandler` 调用。它没有业务输入，返回响应结构指针和错误；`nil` 表示本次处理成功，Handler 随后将响应序列化为 JSON。

打开 `services/lab-api/etc/lab-api.yaml`，把生成的监听地址改为本地回环地址，本轮完整配置为：

```yaml
Name: lab-api
Host: 127.0.0.1
Port: 8888
```

启动顺序：`lab.go` 解析 `-f` 参数 → 读取 YAML → 创建 HTTP Server → 创建 ServiceContext → 注册路由 → 开始监听。

请求顺序：`GET /healthz` → 已注册的 HealthHandler → NewHealthLogic → Health → Handler 写出 JSON 响应。

`ServiceContext` 负责组装共享依赖；`HealthLogic` 的 `ctx` 是当前请求的上下文。数据库连接池会放在哪里，等实际接入时结合代码讲解。

## 与当前实现有关的面试追问

1. **Handler 与 Logic 各负责什么？** 此时 Handler 负责衔接 HTTP 和 Go 逻辑、处理返回值；Logic 计算业务响应。后续会在真实业务中说明验证规则应该放在哪里。
2. **健康检查成功是否等于系统完全可用？** 当前只证明 API 可以处理这个请求。数据库、RPC 和登录链路尚未被检查；涉及依赖就绪的检查要在后续有对应依赖时实现。
3. **使用 go-zero 就能叫微服务项目吗？** 框架选择本身不能证明服务拆分。要能展示独立进程、业务职责以及服务间调用；本章仅完成其中的 API 入口。
